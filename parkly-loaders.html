Parkly · loading states · v1

The mark,
waiting.

Four loaders built from the logo's own dot lattice — the same 5×5 grid, the same 21.5 pitch, lifted straight out of mark.svg. The wait ends by becoming the mark.

01 — provenance

It isn't a new shape.

The mark carries sixteen lit cells in a five-by-five field. Every loader here animates that exact field, so a Parkly spinner is never a generic dot grid wearing brand colour — it is the logo, mid-thought.

PropertyValueSource

one field, scaled — cell and pitch never change

Every size is the same 107.5 viewBox — a 20.5 cell on a 21.5 pitch, so the 1.0 gutter scales with it. Nothing is re-drawn per size and nothing is nudged; the field stays square from a button to a splash screen.

02 — the set

One per moment.

Each variant is tied to a place Parkly actually waits. A loader that means nothing in particular gets used everywhere and reads as noise.

Resolve

Cold app boot and full-page loads. Flickers while it waits, then settles into the mark when the data lands.

2.05s25 cellssteps(1)

Scan

The QR camera screen and sticker lookup. A column sweeps left to right — the gesture the user is already making.

1.50s5 columnsease

Pulse

Sending an alert. Rings travel outward from the centre — a signal leaving, not a wheel turning.

1.70s3 ringsease

Hold

Buttons and list rows. At 24px the per-cell flicker turns to mush, so this breathes the mark whole instead.

1.40s16 litease
03 — completion

Landing the wait.

A spinner that simply vanishes wastes the one moment the user is already looking. Resolve ends on the mark, holds a beat, then hands off.

04 — implementation

Drop-in, no build step.

Pure CSS on inline SVG — no dependency, no bundler, which is what public/css/app.css needs. Per-cell timing rides on one custom property, so the markup stays flat.

/* app.css — the lattice */
.pk-load rect          { fill: var(--cell-off); }
.pk-load.v-resolve rect{ fill: var(--accent); opacity: .14;
                         animation: pk-flick 2.05s var(--d) infinite steps(1,end); }
.pk-load.v-resolve.done rect     { animation: none; opacity: .08;
                                   transition: opacity .5s var(--sd); }
.pk-load.v-resolve.done rect.lg  { opacity: 1; }

@keyframes pk-flick {
  0%, 100% { opacity: .14 }
  45%      { opacity: .14 }
  50%, 72% { opacity: 1   }
  78%      { opacity: .14 }
}

@media (prefers-reduced-motion: reduce) {
  .pk-load rect     { animation: none; opacity: .14 }
  .pk-load rect.lg  { opacity: 1 }
}
<!-- 25 cells, x/y = col*21.5, row*21.5 -->
<svg class="pk-load v-resolve" viewBox="0 0 107.5 107.5"
     role="img" aria-label="Loading">
  <rect class="lg" x="0"  y="0" width="20.5" height="20.5" style="--d:.31s"/>
  <rect          x="64.5" y="0" width="20.5" height="20.5" style="--d:.07s"/>
  <!-- … class="lg" marks the 16 cells the mark itself lights -->
</svg>

<!-- when the data arrives -->
el.classList.add('done');

The mobile app can't use this directly — React Native has no CSS keyframes. Rebuild it with Reanimated, which mobile/ already depends on: one useSharedValue per cell driving opacity, same delays, same lattice. The prefers-reduced-motion equivalent is AccessibilityInfo.isReduceMotionEnabled.
